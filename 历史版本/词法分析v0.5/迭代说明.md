v0.5 实现内容

说人话就是：
新的结构体：错误errlog表
数值格式校验 （新函数 readNumber ）
块注释闭合检查 （新函数 readBlockComment 


1. 换行恢复 class=37 ：每个换行作为`\n` token 输出，归属于它结束的那一行
2. 错误日志表 ErrLog + 独立 log 文件 ：`errAdd` 收集（行号+printf 风格信息，控制台同步打印），`writeErrLog` 输出`error_log_<输入名>.txt` ，无错误也写文件说明
3. 非法字符/未支持关键字 ：`@` 、`:` 等编码表外字符 → “无法识别的非法字符”；`double` （另含 void/long/short 等常见但编码表不支持的类型词）→ “未支持的关键字”，不进三表
4. 块注释闭合检查 （新函数 readBlockComment ）：`/*` 读到`*/` 正常跳过并计数跨行；遇`#` /EOF 未闭合 → 报“缺少 /”；`*/` 没有开头 → 报“缺少 / ：孤立的 */”
5. 数值格式校验 （新函数 readNumber ）：合法十六进制`0x3F` 、科学计数法`1.05e2` 识别为 class=12 并进入 constL（描述分别为“十六进制常量”“科学计数法常量”）；`0x3G` 、`0x` 缺数字、`1.05e` 残缺指数、`12ab` 非法后缀均报错
6. 拼写错误按标识符 ：`swich` 、`retrun` 不报错，按 class=11 正常进 nameL

bianxi写了三个测试结果

用例 退出码 结果 input-v5-1.txt 0 0 错误，30 个 token，hex/科学计数法/换行编码均正确 input-v5-2.txt 1 2 错误：double(行2)、@(行3)；swich/retrun 进 nameL 不报错 input-v5-3.txt 1 4 错误：0x3G(行2)、孤立 */(行3)、1.05e(行3)、注释未闭合(行5)

另外 v5 支持`io_v5.exe <输入文件>` 命令行传参，所有输出文件（token/nameL/constL/error_log/output 文本）自动按输入文件名加后缀，多次运行不会互相覆盖。过程中还修了两个小问题：块注释内出现字面`*/` 提前闭合注释导致编译失败；残缺科学计数法报错时误截掉了尾部的`e` 。
